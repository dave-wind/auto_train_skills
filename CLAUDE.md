# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Project Is

A **generic skill continuous training framework** for Claude Code project-level skills. It turns SKILL.md (a prompt artifact) into something measurable, iteratable, and version-controlled — prompt engineering as an engineering discipline.

The framework complements `/skill-creator` (which creates skills) by providing the ability to systematically evaluate and iterate on them.

## 改进 Skill 的工作流

当 `skills/<name>/TRAINING-FEEDBACK.md` 存在时，这是最新一轮训练的分析结果，直接读取它并协助修改 SKILL.md。

**重要：不要只看报告摘要就改 SKILL.md。** TRAINING-FEEDBACK.md 里的分析是 LLM 基于摘要生成的。改动前必须阅读一手数据来验证你的判断：

1. **实际模型输出**：`skill-training-framework/workspaces/<name>/iteration-N/eval-*/with_skill/run-*/outputs/output.txt`
2. **逐条评分详情**：`skill-training-framework/workspaces/<name>/iteration-N/grading/eval-*-with_skill-run-*.json`
3. **对比上一轮**：看同类 eval 在上一个 iteration 的输出，确认退步/进步是真实的

先读 TRAINING-FEEDBACK.md 了解全局，再读一手数据验证/修正判断，最后再改 SKILL.md。

**标准循环（所有命令在项目根目录执行）：**

```bash
# 1. 收集数据（执行 eval × N runs + 评分 + 汇总 + 报告）
make train SKILL=<name>

# 2. 生成改进建议 → 写入 skills/<name>/TRAINING-FEEDBACK.md
make suggest SKILL=<name>

# 3. 在当前 Claude 对话里改进 SKILL.md
#    告诉 Claude："帮我改进 <name> skill"
#    Claude 会读 TRAINING-FEEDBACK.md，协助修改

# 4. 验证改动效果
make train SKILL=<name>
make diff  SKILL=<name>

# 5. 部署到全局（~/.claude/skills/ 和 ~/.agent/skills/）
make deploy SKILL=<name>
```

**TRAINING-FEEDBACK.md 包含什么（Claude 读取时需要知道）：**
- 失败模式分析——已归纳为 2-4 个根因，不是逐条列失败
- 修改方向——原则级别，不是规则
- 不要改的部分——避免破坏已有效果
- 过拟合警告
- Skill 文件路径（Claude 按需读取 SKILL.md 及 references/、agents/ 等）

**改 SKILL.md 的原则：**
- 写原则不写规则——解释 why，而非堆 MUST/NEVER
- 不要针对单个 eval 写死规则（过拟合）
- 删掉没起作用的指令，保持 prompt 精简
- 不要动 TRAINING-FEEDBACK.md 里"What NOT to change"列出的部分

## Commands

All `make` commands run from the **project root directory**. Prerequisites: `claude` CLI, `uv`, `jq`.

```bash
# Dependency check
make check

# List trainable skills
make list

# Full training iteration (run×N → grade → benchmark → report)
make train SKILL=<name>              # 默认每个 eval 跑 3 次取均值
make train SKILL=<name> RUNS=1       # 单次运行（旧行为，不取均值）

# Individual steps
make run SKILL=<name>                # Execute evals × N runs, baseline 缓存
make grade SKILL=<name>              # LLM-as-judge scoring (每个 run 独立评分)
make grade SKILL=<name> FORCE=1      # 重跑所有评分(包括已有的,用于修复坏数据)
make benchmark SKILL=<name>          # Aggregate across runs → benchmark.json
make report SKILL=<name>             # Generate markdown report with variance

# Compare two iterations
make diff SKILL=<name>

# Generate improvement feedback doc → skills/<name>/TRAINING-FEEDBACK.md
make suggest SKILL=<name>

# Generate test sets
make generate-evals SKILL=<name>       # AI-generate capability evals from SKILL.md
make generate-triggers SKILL=<name>    # Inversion-mode trigger evals (hard negative mining)
make init SKILL=<name>                 # Create empty evals template for manual writing

# Trigger rate optimization (delegates to official skill-creator)
make trigger-eval SKILL=<name>
make trigger-optimize SKILL=<name>

# Deploy to global skill dirs
make deploy SKILL=<name>

# Clean workspace + baseline cache
make clean SKILL=<name>
```

## Architecture

### Two Independent Training Dimensions

- **Capability evaluation** (SKILL.md body): Tests whether the skill performs well after being triggered. Uses `make train`.
- **Trigger rate optimization** (SKILL.md description/frontmatter): Tests whether the skill is correctly triggered. Uses official `skill-creator`'s `run_loop.py`.

These target different parts of SKILL.md and must not be mixed.

### Multi-run Averaging

Each eval runs **N times** (default 3, configurable via `RUNS` variable) to reduce LLM output variance. Results show mean pass rate with min-max range.

**Baseline caching:** `without_skill` runs are cached in `workspaces/<name>/baseline/` after the first iteration. Subsequent runs reuse the cache, saving ~50% API calls.

```
Iteration 1: with_skill × N runs (new) + without_skill × N runs (new, then cache)
Iteration 2: with_skill × N runs (new) + without_skill × N runs (from cache)
```

### Training Pipeline (per iteration)

```
SKILL.md + evals.json
       ↓
run_evals.py      — calls `claude -p` × N runs × 2 configs (with/without skill)
       ↓
grade.py          — calls `claude -p` as LLM-as-judge for each run, scores each expectation
       ↓
benchmark.py      — aggregates across runs: mean pass_rate, min-max range, timing stats
       ↓
report.py         — generates report.md with variance display (e.g., "0.65 (0.60-0.80, n=3)")
```

### Directory Layout

- `skills/<name>/SKILL.md` — The skill definition (YAML frontmatter + body). Required.
- `skills/<name>/TRAINING-FEEDBACK.md` — Generated by `make suggest`. Claude's entry point for skill improvement.
- `skills/<name>/evals/evals.json` — Capability test set. Required for training.
- `skills/<name>/evals/trigger-evals.json` — Trigger test set. Optional.
- `skill-training-framework/workspaces/<name>/baseline/` — Cached without_skill baseline (auto-generated).
- `skill-training-framework/workspaces/<name>/iteration-N/` — Training outputs (auto-generated, not committed).

### Workspace Structure (per iteration)

```
iteration-N/
├── eval-1/
│   ├── eval_metadata.json
│   ├── with_skill/
│   │   ├── run-1/outputs/output.txt, transcript.md, timing.json
│   │   ├── run-2/...
│   │   └── run-3/...
│   └── without_skill/          (restored from baseline cache)
│       └── run-1/... run-3/...
├── grading/
│   ├── eval-1-with_skill-run-1.json
│   ├── eval-1-with_skill-run-2.json
│   ├── eval-1-without_skill-run-1.json
│   └── ...
├── benchmark.json              # aggregated: eval_summary + run_summary + per-run details
└── report.md                   # human-readable: mean ± range, failed expectations by run
```

### Key Design Decisions

- **All commands run from project root** — single working directory, no `cd` needed.
- **Multi-run averaging (default 3)** — single `claude -p` calls have high variance; 3 runs with mean+range gives reliable measurements.
- **Baseline caching** — `without_skill` results don't change between iterations (same model, same prompt), so we cache and reuse them.
- **with_skill vs without_skill baseline** — delta is the skill's true value.
- **Inversion mode** for trigger-evals — generates hard negatives by twisting intent while keeping domain keywords (6 patterns: scale, direction, tool substitution, adjacent domain, meta-request, overkill).
- **TRAINING-FEEDBACK.md in skills/** — placed next to SKILL.md so Claude can find it in a fresh conversation without navigating workspaces.
- **Skill contract**: any skill just needs `skills/<name>/SKILL.md` + `skills/<name>/evals/evals.json` to be trainable.
- **Backward compatible** — `RUNS=1 make train` produces same output format as before; old iterations are readable by all scripts.

### Script Dependencies

All scripts under `skill-training-framework/scripts/` share `utils.py` for JSON I/O, path resolution, and skill/eval loading. Pure Python stdlib, no external dependencies — shell out to `claude -p` for all LLM calls. Run via `uv run`.
